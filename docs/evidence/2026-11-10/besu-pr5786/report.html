The rule and the finding

EIP-4844 calculates the new header’s excess blob gas from the parent header, not the block being built.

return parent.excess_blob_gas + parent.blob_gas_used - TARGET_BLOB_GAS_PER_BLOCK

What the model flagged before the fix

Location: AbstractBlockCreator.computeExcessBlobGas

CancunGasCalculator and ExcessBlobGasCalculator correctly implement calc_excess_blob_gas(parent), including defaulting missing parent excess_blob_gas/blob_gas_used to 0 for the first post-fork block. However, AbstractBlockCreator.computeExcessBlobGas calculates the new block header's excessBlobGas as gasCalculator.computeExcessBlobGas(parentHeader.getExcessBlobGas().orElse(0L), newBlobsCount), where newBlobsCount is the blob count of the block being created, and then stores it via builder.excessBlobGas(usage.excessBlobGas). This computes parent.excess_blob_gas + current_block.blob_gas_used - TARGET_BLOB_GAS_PER_BLOCK instead of the specified parent.excess_blob_gas + parent.blob_gas_used - TARGET_BLOB_GAS_PER_BLOCK. It never reads parentHeader.getBlobGasUsed(). For example, a first post-fork block containing the maximum blobs would incorrectly store excess_blob_gas=393216 instead of 0.

Suggested fix: Set the new header's excessBlobGas using the parent header only, e.g. calculateExcessBlobGasForParent(newProtocolSpec, parentHeader) or computeExcessBlobGas(parentExcess.orElse(0L), parentHeader.getBlobGasUsed().orElse(0L)). Use newBlobsCount only to calculate the new block's blobGasUsed.
